# SDAR 格式说明

适用版本：SDA 0.9.3（延续 0.9.26 的 SDAR 格式实现）。本文介绍当前已经实现的格式、导出流程和独立读取接口。
应用版本、容器版本和编解码器版本分别管理，不能把 `0.9.26` 当作文件协议版本。

## 一、SDAR 保存什么

SDAR 保存独立的床声道或“床声道＋对象”音频、以采样时间为基准的场景信息、混音参数和需要的渲染资源。
播放设备读取同一份文件中的场景与资源，再渲染到目标扬声器或耳机布局。
文件不靠歌曲名、软件数据库、本机预设名称或某次渲染结果来决定声音。

| 显示格式 | 编码 ID | 场景内容 |
| --- | --- | --- |
| SDAR Bed Channel | `SDAR` | 床声道、声道几何、混音参数和资源 |
| SDAR Bed Channel with Objects | `SDAR` | 床声道以及独立对象音频与对象自动化 |

“格式名称”和“编码 ID”是真实封装字段，不能靠修改曲名或轨道标题冒充。
新的 ISO-BMFF 交付文件使用大写 `SDAR` 音频采样项；读取器也保留对旧小写 `sdar` 的兼容。
通用 MediaInfo/播放器需要增加对 SDAR 的解析，才能展示完整格式名称或解码音频。

## 二、WAV 母版、SDAR 和 M4A 的区别

| 文件 | 用途与编码 | 电脑端 | 移动端 |
| --- | --- | --- | --- |
| SDA WAV / RF64 | 可编辑母版；PCM24 音频，附带 SDA 元数据，ADM 来源还保留原始 ADM 信息 | 可播放、换房间、修改调优参数，再导出 | 按文件参数只读播放 |
| `.sdar` | 无损交付；SDA Bed Lossless v2，保留需要的场景及资源；有原始 WAV 归档时可以还原母版 | 只读播放；支持的文件可还原 WAV 后编辑 | 按文件参数只读播放 |
| SDA `.m4a` | 体积较小的交付文件；床声道默认 SDA Bed Compact v1，也可选择无损 | 只读播放 | 按文件参数只读播放，默认目标布局 7.1.4 |

只有内容确实为母版的 WAV/RF64 能进入母版编辑流程。改扩展名不能把交付文件变成母版。
M4A 交付文件不携带用于还原原始 WAV 的完整归档，不是原始母版的替代品。

M4A 是容器后缀，不代表内部必须使用 AAC。本项目新导出的 SDA M4A 使用 SDAR 编码，
不是 AAC、MP3 或把普通 PCM 改个标题。它需要支持 SDAR 的解码器和对应渲染器；
普通播放器能够读取部分标准标签，并不表示能够播放 SDAR 音频。
这是一套专用格式与解码协议，不是依靠加密限制第三方实现。

## 三、采样率、精度、码率和声道

推荐母版采用 48 kHz、24-bit PCM。导出窗口提供的采样率选项应按实际需求选择；
换采样率会经过采样率转换，无损压缩不会使已经转换的采样网格重新等同于原始母版。

- `.sdar` 默认无损编码，码率随内容变化，不使用一个固定目标码率强行压缩。
- 床声道 M4A 默认目标码率为 1536 kbps；较低码率选项是明确的交付质量选择。
- 独立对象场景默认优先无损；选择有损对象交付时使用整个场景的码率档位，不能把床声道码率直接套到大量独立对象上。
- 有损文件中的“24-bit”表示输入/解码 PCM 表示，并不表示经过有损编码后仍拥有无损 24-bit 精度。
- 目标码率只计算音频，封面、歌词、房间/HRTF 资源、场景信息和封装还会占空间。
- Compact 使用受重建误差约束的可变码率。复杂场景可能超过目标码率，以保护安静声道和独立对象的重建质量。

床声道交付可声明 5.1 基础呈现，但仍保存实际编码的后方、高度等声道。
7.1.4、9.1.6 等布局根据完整的声道/对象场景与渲染参数重新计算，不能把文件当作普通六声道下混读取。
对象格式的编码声道数是所有床声道和独立对象音源的总数，不等于最终设备输出声道数。
两种 SDAR ISO-BMFF 交付都只有一条物理音频轨，不会拆成四条音轨让播放器自行拼接。

这不是杜比编码，也不以相同码率宣称与 Dolby Atmos 具有相同的编码质量。
同场景的听感还原需要兼容的渲染实现、资源、输出布局以及一致的监听条件。

## 四、对象如何保存

对象使用稳定 ID，并关联自己的独立 PCM 音源。对象自动化以 48 kHz 母版采样时钟记录，
包括位置/方向、增益、大小或范围、扩散等受支持参数；有明确物理距离时携带距离信息。
移动轨迹保留事件时间及持续时间，跳转后恢复目标时刻的对象状态，不通过改变播放速度追赶进度。

当前扩展还支持版本化的 `zoneExclusion` 和 `horizontalOnly` 约束。
对象自动化、床声道与对象声道的顺序、原始 ADM 标识和必要资源都独立于音频压缩保存。
位置固定的对象也可以有声音；显示是否活跃不能仅用“是否移动”判断。

有对象版本不是给床声道文件贴一个对象标题。源文件没有独立对象时，不能凭空还原原本不存在的对象音源。
当前实现有明确的支持范围与音源数量上限，遇到不支持的必要 ADM 功能或强制扩展会报错，不能静默丢弃后继续冒充完整还原。

## 五、调优、房间和重复处理

文件内的 `sda.render-metadata` 是调优依据，主要包含：

- `scene`：床声道/对象身份、PCM 顺序、几何、声道增益、时长和自动化引用。
- `baked`：已经写入音频的上混、音量/空间平衡、校准增益、峰值余量等处理标志。
- `playbackSnapshot`：文件确认的 HRTF、房间、EQ/FIR、反射、监听与其他运行时参数。
- `assets`：实际 HRTF/BRIR/FIR/房间资源以及 SHA-256 引用。
- `playbackPolicy`、`interchange`：文件参数的权限、版本化渲染约定和必须支持的功能。

播放器必须区分“已经处理进音频”和“需要在播放时执行”。
已经烘焙的处理不能再叠一次；尚未烘焙的处理按文件携带的参数执行，不能覆盖为本机开关值。
例如 ADM 场景转交付文件保留原始音源 PCM，音量/空间平衡可以仍属于运行时操作，
此时文件携带的是启用状态、测量值与策略，不能错误标记成已经完成烘焙。

自定义房间要携带实际资源，不能只写“某某房间”这个名字。
移动端即使没有对应的房间编辑页面或本地预设，也要使用文件内的资源。
缺少必需资源、资源哈希不符或不支持必需的渲染功能时必须报错，不能自动换成默认房间。

要换房间或调整混音，使用电脑端 WAV 母版编辑并重新导出。
已经导出的 SDAR/M4A 不会因为电脑后来换了预设而自行改变。
系统音量和监听者头部姿态仍是播放设备上的用户操作。

## 六、封面、歌词和中文日文标签

- WAV 使用 Unicode ID3v2.4 保存完整文字、APIC 封面、USLT 歌词，以及原始 LRC/TTML/来源与渲染记录。
- WAV 的旧 RIFF INFO 兼容字段仅写入适合其兼容性的 ASCII 内容，完整中日文以 Unicode 元数据为准。
- SDAR/M4A 还写入标准 `udta/meta/ilst` 标签，包括标题、歌手、专辑、年份、曲目/碟号、`covr` 封面和歌词。
- 私有记录保留原始歌词字节、时间、编码信息与来源标签，避免只剩一个显示出来的字符串。

原曲没有的标签不会被当作已有信息补造。第三方检查器对未知音频采样项和歌词类型的展示能力仍可能不同。

## 七、独立接入与命令行工具

格式包提供 `crates/sda-format`、其编译所需的 `vendor/faad2` 源码与说明、格式文档，
以及 Windows x64 的 `bin/windows-x64/sdar-codec.exe`。这里的 FAAD2 用于读取历史 AAC 交付文件，
新 SDAR 编码并不使用 AAC 编码器。构建和分发时应保留包内各依赖的许可及版权说明。

在格式包根目录构建（需 Rust/C 编译工具链及 Cargo 依赖）：

```sh
cargo build --release --locked --manifest-path crates/sda-format/Cargo.toml
cargo test --release --locked --manifest-path crates/sda-format/Cargo.toml
```

Windows PowerShell 中检查真实文件：

```powershell
.\bin\windows-x64\sdar-codec.exe --version
.\bin\windows-x64\sdar-codec.exe inspect "D:\Music\作品.sdar"
.\bin\windows-x64\sdar-codec.exe verify "D:\Music\作品.m4a"
.\bin\windows-x64\sdar-codec.exe restore-master "D:\Music\作品.sdar" "D:\Music\恢复的母版.wav"
```

`restore-master` 只适用于实际保存了可恢复母版归档的文件，不能用来给任意 M4A 补造原始母版。
`serve FILE --layout 7.1.4` 提供版本化的 JSON/二进制拉取、跳转协议；WAV 母版需加 `--allow-wave`。
它返回独立音源 PCM 与场景，调用方仍需实现/接入 `sda.authored-scene` 渲染约定。
**解码器不是完整空间渲染器**，只读 JSON 或直接混成两声道不能替代 HRTF、房间和对象渲染。

Rust 接口入口是 `BedFile::open_interchange` 与 `PreparedResources::renderer_scene`。
渲染期间应保持资源对象有效，不得在使用前释放文件提取的房间与滤波器资源。

## 八、容器和版本识别

当前交付元数据为 `sda.delivery` version 4，渲染元数据与独立场景约定各自使用版本号。
ISO-BMFF 的主要字段包括：

| 字段 | 用途 |
| --- | --- |
| `SDAR` | 音频采样项 / 编码 ID；兼容读取历史小写 `sdar` |
| `sdac` | 真正的编解码器配置和场景格式身份 |
| `sdaf` | 交付清单、完整声道映射、采样率、时间与配置 |
| `sdrm` | 权威渲染元数据 |
| `sdiz` | M4A 中压缩的原始 ID3 与资源记录 |
| `sdwe` | 当前无损 SDAR 中按块压缩保存的原始 WAV 归档 |

无损 v2 包使用 `SBL3`，Compact v1 使用 `SBC2`；支持独立分块、校验和有限内存跳转。
这些是格式版本标识，不是声称使用 MPEG 或 Dolby 编码。
历史 BCH1/BCH2、AAC 交付、无损 v1 和旧 WAV 归档形式按已有兼容路径读取；
新文件必须声明实际需要的功能，不能为适配旧播放器偷偷降低场景语义。

完整字段和二进制约定见随包文档：

- `docs/sda-interchange-v1.md`：当前互操作与独立渲染集成规范。
- `docs/sdar-object-constraints.md`：对象空间约束扩展。
- `docs/sda-compact-quality.md`：有损交付的重建误差保护。
- `docs/sdar-wave-archive.md`：流式 WAV 归档及还原。
- `docs/sdar-bed-lossless-v1.md`、`docs/sdar-bed-channel-v1.md`：历史格式参考；新导出以当前互操作规范为准。

## 九、本次发布与验证范围

0.9.26 汇总此前的床声道/对象导出与跨端读取、文件调优权限、标准标签、房间资源、
ADM 响度校准、声音遮挡与峰值保护等更新，并包含移动端音频输出回调停滞恢复、
对象显示同步和 Android 音频信息弹窗布局修复。

Release 中的 SHA-256 与构建清单用于核对文件和源码提交。
编译、自动化解码/导出测试通过，不等于已经在每一种手机、耳机或扬声器上完成验听。
iOS IPA 为 arm64 未签名包，安装前需要自行签名；Android 包使用项目正式发布签名。
0.9.3 全平台 Release 的附件仅提供对应安装包；格式规范与源码在仓库中查阅，独立格式包保留于 0.9.26 Release。
