# Android / Windows 音量平衡对齐

Android 原生播放链路复用 Windows 渲染器的节目总增益和 40 ms 平滑包络；不修改对象、声床、KU100 或房间资产。

## 测量与策略

- 测量真实双声道母带，或 MPEG-H 上游 PCM24 双声道参考混音，绝不测量对象单通道或最终耳机输出。
- 双声道分类要求 L/R（包括 Left/Right、FrontLeft/FrontRight），且没有对象声明/事件；ADM 排除。多声道 Dolby/ADM 不套用响度增益，Dolby dialnorm 不转换成增益。
- BS.1770 K 加权，400 ms 窗口、100 ms 步进、−70 LUFS 绝对门限和 −10 LU 相对门限。目标 −18 LUFS，仅衰减。
- 普通双声道采用与 Windows 相同的 49 tap 真峰值估计，−1 dBTP 上限；MPEG-H 不用量化参考混音的真峰值限制 SDA 对象渲染总增益。
- 每 8 个有效测量帧附带累计测量；57 个绝对门控有效块后可第一次应用，此后至少增加 50 块才更新。含大量静音时不会简单地按六秒触发。
- 增益按照样本时钟分步调度，每步最多 0.75 dB、通常间隔 250 ms，整段过渡最多 4 秒；渲染器再应用既有平滑包络。
- 开关默认关闭且持久化。关闭时旁路总增益，解码测量仍运行；开启不预扫描、不启用第二个解码器。

## 缓存与生命周期

以原始完整文件内容 SHA-256、48 kHz 播放采样率和 v6 算法版本标识缓存。临时 MP4 → MHAS 提取沿用原文件身份。缓存命中时，在第一批 PCM 前设置总增益。

只有正常完成解码、节目符合条件、累计至少 57 个有效块且响度有限时才保存；停止/中断/解码失败不能缓存局部片段。损坏缓存视为未命中。换曲或 seek 清空测量和节目状态，但保留用户开关。

MPEG-H 每个 access unit 解码后立即复制对应参考 PCM，避免一次输入包含多个单元时误用最后一个参考输出。参考样本数可能因解码器延迟裁切而与对象捕获样本数不同。

## 回归验证

`node scripts/test/mobile-volume-balance.test.cjs` 直接运行 Windows 当前 TypeScript 测量器和播放调度方法，核对提交的黄金向量及桥接/缓存接线。Windows 策略发生变化时需人工检查后用 `--update` 更新向量。

原生 `balance` 单元测试核对 44.1/48/96/192 kHz 的响度和真峰值、输入分块独立性、保护性增益、样本时钟调度、分类、缓存及关闭时持续测量。MPEG-H 测试核对任意输入分块下对象 PCM/事件/参考 PCM 一致；移动引擎集成测试覆盖缓存增益、开关、对象节目旁路和 seek 状态。

当前 Android 输出为 48 kHz，仍使用既有解码器支持范围；此功能不增加 ALAC/ADM 等新的解码器，也不宣称设备听感验证已完成。
