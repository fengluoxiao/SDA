# SDA interchange and independent renderer integration

This contract is data driven. A file carries channel identities/geometry,
acknowledged render settings, baked-processing flags and the actual required
response/filter resources. A player must not look up songs, filenames, preset
names or Git revisions to decide how to render it.

## Carriers and application roles

| Carrier | Audio | Authoring in desktop SDA | Mobile SDA |
| --- | --- | --- | --- |
| Authored WAV/RF64 | 48 kHz PCM24 bed, ADM + SDA metadata | Room/tuning editing of the master | Read-only file-authored playback |
| SDAR | SDA Bed Lossless v2, standard ISO-BMFF envelope | Read-only delivery; can restore its original WAV envelope | Read-only file-authored playback |
| SDA M4A | SDA Bed Compact v1 by default, optional lossless | Read-only delivery | Read-only file-authored playback |

Default compact delivery is 48 kHz, 1536 kbps audio target. 1024/768 kbps are
explicit lower-bitrate choices. The 24-bit field describes decoded/input PCM,
not 24-bit lossless precision of a lossy stream. Target bitrate excludes covers,
lyrics, filter resources and container overhead. It is not a claim of Dolby
codec identity or equivalent perceptual quality. Keep the WAV/lossless source
for mastering. All coded bed channels survive; a six-channel base presentation
never discards the rear/height signals needed for larger render layouts.

Identify by contents, not extensions. Only an actual authored WAV/RF64 is an
editable master in desktop SDA. Renaming a delivery does not unlock it.
Ordinary source music retains the existing player controls. Mobile never
exposes master-authoring operations.

## Read without the desktop/mobile application

The Rust crate crates/sda-format has no Electron/React dependency. Its public
entry point is BedFile::open_interchange(path), which accepts authored WAV,
legacy/private SDAR and the ISO-BMFF SDAR/M4A deliveries. Metadata and embedded
assets are returned from the file, not application preferences.

~~~rust
let mut bed = sda_format::BedFile::open_interchange(path)?;
let editable_master = bed.is_editable_master();
let resources = sda_format::PreparedResources::new(&bed.metadata)?;
let scene = resources.renderer_scene(&bed.metadata, "7.1.4")?;
// Pass scene to an implementation of sda.authored-scene version 1.
// Read PCM in bounded blocks, preserving source sample positions and labels.
while !bed.finished() {
    let pcm = bed.read(4096)?;
    // submit pcm and its sample clock to the renderer
}
~~~

The standalone sdar-codec inspect FILE command returns schema
sda.interchange-inspection/version 1, role, complete source/render metadata,
channel metadata and the asset inventory. No app database is required.
serve FILE --layout 7.1.4 provides the version-1 JSON/binary pull/seek protocol
and a prepared scene. For WAV, add --allow-wave when using serve. The decoder
returns 48 kHz PCM to the renderer; resampled coded rates retain the original
master timeline. Keep PreparedResources alive during rendering; its extracted
files are source-owned and removed on close. This is not a rendered-audio or
loudness cache.

## Rendering contract

The authoritative record remains sda.render-metadata/version 1:

- scene: bed channel IDs, PCM order, source IDs, spherical/Cartesian geometry,
  channel gains and duration. Never infer these from a fixed 5.1 table.
- baked: applied source upmix, volume/spatial balance, calibration gain,
  peak headroom and dither. Never apply these a second time.
- playbackSnapshot: file-authored HRTF, EQ, room, reflection split, speaker
  calibration, bass management, monitoring and other runtime settings.
- assets: SHA-256 references to the actual HRTF/BRIR/FIR/room resources.
  Restore these exact resources, including custom profiles unavailable in the
  local room library. Missing or invalid required resources are errors.
- playbackPolicy: file authority and no duplicate processing. Listener system
  volume/head pose remain user controlled.
- interchange: sda.interchange/version 1, rendererContract
  sda.authored-scene/version 1, requiredFeatures and an error policy for
  unsupported mandatory processing.

The reference scene is generated by PreparedResources::renderer_scene. Use the
reference native renderer library or an implementation of that versioned
contract; merely parsing JSON in an arbitrary player does not recreate DSP.
The rendererRevision field is provenance, not a preset key or playback branch.
No built-in room lookup may replace a required embedded room.

Only WAV masters can re-author their room in desktop SDA. Edits pause/apply/
resume transactionally, preserve an explicit user pause and roll back on
failure. Export uses the last acknowledged file scene. It rewrites metadata
and embeds the selected room, preserving bed PCM, channel geometry and baked
processing exactly. Exporting WAV, SDAR or M4A then carries that updated tuning.
An existing delivery does not change when a desktop preset is changed later.

## Standard and authoritative metadata

WAV uses Unicode ID3v2.4 for complete descriptive tags, APIC artwork, USLT
lyrics and GEOB original LRC/TTML/source/render records. Legacy RIFF INFO
compatibility fields are ASCII-only because readers disagree about their
Unicode encoding; CJK text must not be put there and allowed to override ID3.
ADM axml/chna preserve standardized bed identities/positions.

Both new SDAR and M4A use brand sda1, one physical audio track/ID and sample
entry sdar. Standard udta/meta/ilst contains Unicode title, artist, album,
year, track/disc, covr artwork, lyrics and source comments. Private metadata
retains exact original lyric bytes/timestamps/encodings and source tags.
Generic tools can inspect these standard tags without an SDA audio decoder.
Actual audio/tuning playback still requires an SDA decoder/renderer.

sda.delivery/version 4 in sdaf declares codec/profile, coded sample rate,
master duration, complete channel map, 5.1 base, 7.1.4 mobile default and the
stream configuration. sdac identifies the real independent codec; the handler
name/title alone never establishes a codec.

- sdrm: authoritative render JSON.
- M4A sdiz: zlib-compressed original ID3/resource bundle.
- SDAR sdwh/sdwt: original WAV prefix and zlib-compressed post-PCM chunks.
  These preserve exact master restoration without a second copy of the assets.
- public freeform com.sda.renderer/interchange-v1 describes these actual box
  locations, compression and read-only delivery role.

Resource decompression is bounded. Asset hashes, duplicate/conflicting
metadata authorities, channel maps, packet timelines and CRCs are validated.
The original private BCH1/BCH2 SDAR, legacy AAC transports and lossless-v1
remain readable. New exports never invoke an AAC/MPEG audio encoder.

## Codec packets

SDA Bed Lossless v2 uses independent blocks of up to 4096 PCM24 frames, magic
SBL3. SDA Bed Compact v1 uses SBC2 and the same sized blocks. Start sample u64,
frame count u16, channel count u8 and PCM representation bits u8 follow the
four-byte magic (little endian). Each channel descriptor is 84 bytes: reference
indices a/b, shift, five reserved zero bytes, 18 signed Q23 coefficients and
payload length u32. References must be earlier channels or 255 (none).
Coefficients describe eight causal self-history taps and five current/past taps
for each reference. They are carried in the stream, not fitted by a decoder.

Lossless predicts directly from reconstructed samples and codes exact integer
residuals. Compact separates the feed-forward cross-channel signal from the
residual history, preserving interchannel correlation while quantizing the
residual. All recurrence state is checked; output must remain signed PCM24.
Compact is lossy and must never be marked lossless.

Each channel payload separately codes its first min(8,n) residuals and the rest.
An entropy section has k/run-k/mode/reserved bytes and byte length u32. k=255
means all zeros and no data. Otherwise mode 0 is zigzag Rice coding; mode 1
uses a one-bit selector: one + Rice(nonzero zigzag - 1), or zero +
Rice(zero-run length - 1). Bits are MSB first; trailing padding is zero.
A packet CRC32 IEEE is appended before byte escaping (FE -> FE 00,
FF -> FE 01). Independent blocks permit bounded seeking without decoder
history from an unrelated song. The final partial block has its exact duration
in stts; movie/track/media clocks use the coded sample rate without millisecond
rounding or AAC priming.

## Evolution

Unsupported required features must fail rather than use a default simulation.
An incompatible processing/scene change must also bump its major schema or
renderer-contract version so old readers refuse it. Objects, automation and
VST3 authoring are not implemented by the current Bed Channel profile; do not
claim Bed Channel With Objects for an empty or unsupported object scene.
The format crate, scene interface and reference renderer can move to a separate
repository without changing existing files. Application UI/storage paths are
not part of this contract.


## Object scene extension (object-scene-v1)

`SDAR Bed Channel With Objects` uses `scene.kind = "bed-objects"` and the genuine private codec profile `sdar-bed-channel-with-objects`. The render-metadata and delivery envelopes remain version 1 / version 4 respectively; the required features **object-scene-v1** and **sample-clock-object-automation-v1** are mandatory. A bed-only reader must reject this profile. The same independent predictive PCM coder carries 1–128 lanes. These lanes are source stems, not device output channels. There is exactly one physical ISO-BMFF audio track; its channel map covers every bed and object PCM lane. The object profile declares the real coded lane count, rather than describing the scene as a six-channel downmix.

### Scene identity and time

`scene.channels` lists all PCM lanes in their original order, with one-based `pcmChannel`, stable ID, `kind` (bed/object), track UID, original ADM channel/track/pack format IDs and original display name. Beds have named speaker roles. Object lanes also carry a numeric `objectId` and a `sourceId` of `obj:<id>`. `scene.objects` explicitly maps each stable object ID to its separate PCM lane. The original ADM names do not become routing IDs.

`scene.automation` points to a SHA-256-addressed embedded resource:

```json
{"schema":"sda.object-timeline","version":1,"encoding":"zlib-json","asset":"<sha256-of-compressed-resource>","eventCount":105928,"sampleRate":48000}
```

The zlib payload is UTF-8 JSON with `schema: sda.object-timeline`, `version: 1`, `sampleRate: 48000`, `durationSamples`, `coordinateSystem`, `interpolation` and `events`. Each event contains an exact integer `samplePos`, stable numeric `id`, `hasPos`, ADM Cartesian `pos`, `gainDb`, `size` (width/depth/height), `diffuse`, `anchor`, nullable metric `distanceM`, `distanceInfinite`, nullable `screenFactor`/`depthFactor`, and integer `rampDuration`. Derived `position` gives azimuth/elevation/reference distance for inspection; it never invents physical metres. ADM Cartesian X is right, Y front and Z up; azimuth is positive left. Ordinary zero-radius points have elevation zero in the derived inspection data. Original ADM coordinates and their declarations remain in the preserved XML.

An event's target ramp starts **at** `samplePos`; a zero ramp is an immediate step. Position, extent and diffusion interpolate linearly, as in the renderer; scalar gain interpolates in linear amplitude. A subsequent event interrupts the previous ramp. Every object has an initial state at sample zero, including a silent initial event when its active interval begins later. End/gap mute events preserve active intervals. Production timecode in audioProgramme.start is not added to PCM sample positions. Original decimal timestamps, block durations and interpolation declarations are additionally retained in the source ADM.

`BedFile.objects.events(start, frames)` returns only the current interval's events and reconstructs the interrupted ramp after any discontinuity. Recovery emits an immediate current-state event, followed at the same sample by a target event with the exact remaining ramp. Events with equal sample/ID keep their original order. Mobile rebases these reconstructed events to its reset decoder clock; desktop uses the source PCM clock. A seeking SDK consumer must reset the renderer origin to the returned source start before submitting the recovery frame, so its immediate current-state event is applied before the remaining target ramp. Never derive this timeline from the UI visualization refresh rate.

For imported ADM DirectSpeakers, `sourceMapping.kind = adm-direct-speaker-role` preserves the original speaker-role routing across output layouts. Its original raw Cartesian geometry remains in the channel metadata. These beds do not become moving objects or receive an additional spherical reinterpretation of the ADM room cube. Dynamic objects keep their original position events. Output layout changes (including mobile's default 7.1.4 and desktop 9.1.6) route the retained scene at playback, rather than selecting a pre-rendered audio variant.

### Provenance, resources and file roles

WAV masters retain standard original axml/chna/dbmd chunks and the original PCM bytes. `render.provenance.originalMetadata` additionally references exact zlib-compressed axml/chna/dbmd/bext/iXML payloads where present, with raw SHA-256 and raw byte length. These source resources also travel in M4A and SDAR, together with the normalized timeline, tags and portable HRTF/room/headphone assets. Missing required timeline/resources, invalid mappings and unsupported object semantics are errors.

Delivery object data lives inside private SDA metadata/resources and actual SDA coded packets. Ordinary AAC/MPEG decoders do not decode the scene; an SDA-capable renderer must interpret its declared contract. This is format-level interoperability, **not encryption or DRM**. Standard public song tags/artwork/lyrics remain available to generic inspectors. WAV masters expose standard ADM for other compatible tools. SDAR/M4A delivery files remain read-only; only desktop WAV masters support room/tuning reauthoring, with unchanged object PCM and automation. Mobile uses file-authored rendering and skips local balance/upmix presets.

Import transfers the original master mix at unity and records HRTF/room/monitoring settings; it does not upmix or rebake programme/spatial balance. The renderer still applies its final output protection. Original Dolby dbmd is preserved as provenance, not presented as Dolby decoding/licensing or a promise of Dolby binaural-render equivalence.

Object M4A defaults to lossless coding to preserve the complete independent stems. Explicit compact export supports aggregate 3072/6144/12288/24576 kbps at 48 kHz. These are whole-scene rates, not per-object rates, and are not claims of Dolby codec quality or perceptual equivalence. Existing bed rates remain unchanged. Predictive model search is bounded for large source counts; packets preserve their own reconstruction model and remain independently seekable.

Current import support follows the shared ADM parser: normalized Cartesian extents and point spherical objects; unsupported interactive/alternative programmes, nonzero spherical extents, channel-lock/divergence/screen-lock features, and delivery zoneExclusion/horizontalOnly requirements fail explicitly. The versioned contract can add such features later without silently dropping source metadata.

Regression: `SDA_FORMAT_CODEC=<sdar-codec> node apps/desktop/test/object-export.test.cjs` verifies interleaved bed/object mapping over 66 lanes, exact PCM24 and ADM master restoration, object extent/diffuse/gain, mid-ramp seek, Unicode source tags, one-track SDAR/M4A and explicit bitrate/profile validation. Shared mobile route verification uses the generated fixture directory: set `SDA_OBJECT_FIXTURE_DIR`, then run the ignored `object_interchange_preserves_mobile_pcm_routes_and_seek_clock` native test explicitly.


### Real-time PCM transport

The `serve` SDK protocol defaults to `interleaved-f32le` for compatibility. `--planar` negotiates `planar-f32le` in both ready/frame `pcmLayout`: all samples of source lane 0, then lane 1, etc., each little-endian Float32. Channel identities, event clocks, frame counts and the 48 kHz timeline are unchanged. Desktop uses this layout to pass exact-sized per-lane typed arrays copied by lane rather than unpack every sample in the UI/main process. Unknown layouts and mid-session layout changes are errors; an older SDK without this field retains its interleaved path. This affects transient PCM transport, not file coding or authored audio.

Render buffering uses source workload (32+ object lanes, or 64+ total lanes with objects), independently of the container/codec name. Existing remote synchronization and tracked-iOS reserve limits retain their policies. Buffer recovery keeps all queued samples on the DAC clock; no playback-rate or sample-skipping catch-up is introduced.

Electron contextBridge does not preserve the efficient shared backing-store representation across exposed API boundaries: a per-lane view of a complete scene buffer can copy the complete scene for each lane. Each returned lane therefore owns exactly `frames * 4` bytes with zero byte offset; the sum of backing-store sizes equals the PCM payload size.
