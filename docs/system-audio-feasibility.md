## 结论与估算口径

技术上可行，正式产品优先采用“虚拟播放端点 → 用户态实时处理 → 指定物理输出”的结构。现有播放器可复用 DSP 和部分设备管理，但输入、时钟和缓冲需要实时模式，不能直接复用文件播放流水线。

| 交付阶段 | 累计投入 | 可验收成果 |
| --- | --- | --- |
| 技术原型 | 1–2 人周 | 用已有合法可用的虚拟端点验证 7.1 PCM → SDA → 有线耳机；测延迟、重复播放与反馈 |

## 路线比较

1. **进程 loopback，无自有内核驱动**：微软 API 可包含一个进程树，或排除某个进程树捕获其他应用。可用于选应用试听或输入实验，并有助于排除 SDA 自身回录。但捕获 API 本身不是输出重定向 API：原应用仍可能直接出声。如何只保留处理后的声音、静音原会话后捕获是否继续、应用重启和输出变化，都必须实测，不能先承诺无驱动全局接管。该 API 文档要求 build 20348+，不能称为所有 Windows 10 都支持；消费版 Windows 10 19045 不满足这个门槛。
2. **虚拟播放设备，推荐正式路线**：应用输出到 SDA 虚拟音箱，SDA 从虚拟端点捕获或通过明确的驱动/用户态通道读取 PCM，处理后送到真实输出。虚拟端点没有物理发声，便于避免原声叠加；物理输出不得重新选择输入虚拟端点。安装可集成到安装器，但需要管理员权限与正确的发行签名。
3. **APO 系统效果**：能在 Windows 音频效果图内执行 DSP，但不是给 Electron 加一个插件即可。涉及端点安装绑定、实时 COM 处理、不同驱动效果链与流格式，并要适配现有独立渲染器架构。更适合后续专门研究，不作为最短首发路线。

SysVAD 是微软 WDM/WaveRT 虚拟音频设备开发样例，不是现成可发布的 SDA 虚拟音频线。仍需确定最简端点拓扑、声道掩码、格式协商、捕获/传输方式、周期与时间戳、流生命周期和安装包。现有 AirPods 蓝牙驱动经验与构建脚本可参考，但它不是音频端点驱动。

### 是否需要重新写 Windows 驱动

正式采用自有虚拟播放设备路线时，需要开发和维护 SDA 的虚拟音频驱动，但可以基于微软 SysVAD 样例，不必从零编写。该驱动负责提供音频端点并把 PCM 交给用户态；双耳渲染、房间和监听 DSP 继续在普通进程中运行，不替换用户现有的物理声卡驱动。

后续原型可先使用现成、合法可用的虚拟声卡，验证实时链路后再决定是否投入自有驱动。第三方驱动能否随 SDA 打包、静默安装或商业分发，必须单独核实授权，不能把可下载使用等同于可再分发。无自有驱动的捕获原型也可研究，但原声抑制和完整输出接管尚不能保证。

## SDA 当前可复用的部分

- HRTF、分区卷积、音箱总线、房间响应、监听/硬件处理和最终耳机 FIR。
- Windows 输出设备 ID、共享输出和格式转换、设备状态、前端设置与 ACK。
- PCM 帧协议和环形缓冲的数据结构思路。

需要新建或改造的部分：

- 原生实时输入；音频数据不绕道 React 状态或逐帧 JSON。
- 独立的实时缓冲策略，不能压缩现有文件播放器的缓冲后让旧场景退化。
- 输入与输出独立设备时钟之间的缓冲水位控制/漂移补偿；静态采样率换算不等于长期时钟同步。
- 主动避免自身回录、原声叠加、源应用退出、静音间隔后的过期队列和恢复爆音。
- 清楚显示输入格式，选择物理输出；退出、崩溃与卸载时恢复先前设备，避免把其他新设置覆盖掉。

仓库核查：`apps/native-renderer/src/main.rs` 设启动 FIFO 为 8192 帧（48 kHz 下 170.7 ms），目标水位为 16384 帧（341.3 ms）。这些是配置值，不是本次实测端到端延迟。`convolution.rs` 默认分区为 1024 帧（21.3 ms）；实时路径应测 128/256 等较小分区的性能，不能只缩缓冲、不做 CPU 和稳定性测试。既有输出仍可复用，但实时路径需要单独的测量和调度设计。

## 第一版合理范围与性能目标

- Windows 11 x64、48 kHz、2.0/5.1/7.1 PCM，一路物理输出，先做有线/USB 耳机。
- 标准桌面播放器、浏览器与普通游戏的多声道输出；立体声仍是立体声源，可使用明确标示的上混。
- 目标端到端新增处理延迟 25–60 ms，用真实回环测量确认，不承诺零延迟或竞技级体验。蓝牙耳机、UU/RDP 自身缓冲不由此目标覆盖。
- 不需要 AI 模型，也不要求用户部署模型；CPU 预算主要取决于卷积、声道数和启用的处理，需在目标硬件上测量。
- 不自动得到其他应用的 Atmos/AC-4 对象：普通 loopback/虚拟 PCM 端点提供的是 PCM 声道数据，不保证保留对象 ID、位置元数据或 Windows Spatial Audio 对象流。系统空间渲染、受保护内容、独占/ASIO 应另行确认，不列为首版保证。
- 不承诺一开始覆盖 9.1.6、所有外部应用和所有第三方虚拟声卡。

## 发布与兼容性成本

微软文档要求硬件开发中心账户关联有效 EV 证书，且需注册硬件开发者计划。测试签名不能作为普通用户默认安装方案；不应要求用户关闭 Secure Boot/安全功能来兑现“开箱即用”。Attestation 文档现有说明限制面向零售的 Windows Update 分发，不能把 attestation 当作 WHCP/HLK 的等价替代。具体自分发/WHCP 路线应在原型阶段确认账户、目标系统和当期政策。

必须做的兼容矩阵包括 Realtek/USB 输出、44.1/48 kHz 差异、蓝牙重连、默认设备切换、睡眠唤醒、源应用重启，以及 RDP/UU。虚拟设备变成默认输出后，远程软件可能捕获到虚拟端点的原始声音而非 SDA 的物理输出，原有“远程共享模式”不代表新路由已兼容。需验证远端究竟采集哪一级，并提供明确路由方案。

## 建议决策

待用户后续决定启动时，建议先投入 1–2 人周做可丢弃的技术原型，测清：7.1 声道映射、处理前后声音是否重复、反馈隔离、延迟与 CPU、连续运行时钟漂移。当前不执行该阶段。原型用测试依赖不等于产品让用户手动部署；正式版的自有驱动和安装体验单独完成。

原型验收应保存有线硬件回环的中位数/P95 延迟、丢帧与欠载计数、至少两小时漂移记录，以及代表性游戏/浏览器输出行为。不满足预算先修架构，不先花时间包装完整 UI。
