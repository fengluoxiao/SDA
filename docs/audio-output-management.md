# 音频输出管理

更新：2026-09-09。

## 使用

在「系统设置 → 音频输出设备」选择输出设备与 WASAPI 访问方式，再点「应用」。使用 SDA 的通用选择器，支持深色、浅色和窄窗口。更改选择不会立即切换声音；成功应用才保存到桌面用户设置的 `audioOutput` 字段。

- **跟随系统默认**：跟随 Windows 常规默认输出端点（eConsole，与此前 CPAL 路径一致）。系统默认变化时重开输出；没有可用输出时最多每 5 秒重试。
- **指定设备**：保存 Windows 端点 ID，不依赖名称或列表顺序。同名设备可以区分；驱动重装可能改变 ID。设备断开时不偷偷转到扬声器。重新连接后点「应用并重试」，或选择另一设备。
- **共享**：采用端点当前的 Windows 混合格式。Windows 可能再应用系统音量、音效或其他处理。
- **独占**：使用真正的 `AUDCLNT_SHAREMODE_EXCLUSIVE`。驱动不支持、设备被占用或系统禁用独占时返回失败，并尝试恢复原来的输出设置。不会把共享模式标为独占。
- **远程兼容 · UU / RDP**：固定采用系统默认端点与共享混音，让远程软件可以采集系统播放声音。此模式在桌面和原生层都会清除冲突的独占/固定端点参数，并持久化 `remoteCompatible:true`。新用户默认启用；已有配置保留，用户可主动切换。输出设备选择在此模式禁用，切回普通共享后可手动指定端点。

独占会绕过共享混音，UU 等使用系统音频采集的远程软件可能无声；因此独占选项标为「本机监听」并提示远程限制。安装了 UU 虚拟音频设备并不等于当前正在远程连接，不根据设备名称擅自选中虚拟端点。远程兼容跟随系统实际默认；远程端若选择采集另一设备，仍需在远程软件中统一采集目标。本软件不能保证第三方远程客户端的音频开关、权限和网络状态。

选择框是准备应用的设置；下方状态是实际已打开的设备与访问方式。实际缓冲时长来自 `GetBufferSize`，不是整条链路延迟。内部渲染固定 48 kHz，双耳左右声道通过既有转换器适配设备采样率；多声道端点仅向前左右输出，其他通道写零，不是多声道直通。

输出中断时主界面提供进入设置的提示。停止消费 FIFO 后播放输出时钟保持；原有 render worker 仍可能填满有限的预缓冲。不会替用户改暂停状态或从头播放。设备恢复后，之前暂停的保持暂停，之前播放的可继续。

## 输出生命周期

`apps/native-renderer/src/output_manager.rs` 直接使用 Windows WASAPI/COM：

1. 主输出线程持有音频客户端与转换器。共享模式使用 `AUDCLNT_STREAMFLAGS_EVENTCALLBACK`，仅在驱动缓冲就绪事件到达后提交音频，恢复此前 CPAL 所使用的共享事件机制；独占仍按缓冲空余量泵送。控制消息检查间隔 2 ms，运行期间申请 1 ms 定时精度，退出时释放。
2. 独立 COM 扫描线程每秒枚举端点及共享格式，仅在设备快照改变时发送消息；属性库/驱动扫描不占用音频泵线程。
3. 手动切换旧端点先做 5 ms 增益淡出并有界等待缓冲排空，关闭后初始化新端点、启动并淡入。等待上限 80 ms；驱动打开耗时另计。
4. 失败后尝试重开先前输出；如果恢复也失败，明确变为不可用，保留原偏好供重试。
5. 跟随默认自动变更时重开输出；固定设备失联时关闭输出，等待手动恢复。不会重建解码器、Engine、布局、HRTF、房间、监听或耳机模拟。
6. 同一端点 ID 的共享采样率发生变化时也重开输出，覆盖部分远程驱动重连时 ID 不变的情况。

独占候选覆盖 48、44.1、96 kHz 双声道，PCM 16/24/32 位和 float32，尝试传统 WAVEFORMATEX 与 WAVEFORMATEXTENSIBLE。每个候选要真实初始化成功才选用；仅 `IsFormatSupported` 成功不算打开成功。对 `AUDCLNT_E_BUFFER_SIZE_NOT_ALIGNED` 取得对齐帧数并创建新客户端重试。共享接受 float32 及 PCM 16/24/32，采样率范围 8–384 kHz、2–32 声道；超出范围明确失败。

原有 FIFO、欠载恢复、输出转换及峰值/跳变诊断保留。桌面日志记录 `audio output` 状态及控制 ACK。渲染健康事件中的采样率仍是渲染时钟；设备真实参数以 `outputDevices.status` 为准。

## 协议与持久化

原生 JSON 控制：

```json
{"type":"listOutputDevices"}
{"type":"setOutputDevice","deviceId":null,"exclusive":false}
{"type":"setOutputDevice","deviceId":null,"exclusive":false,"remoteCompatible":true}
```

状态通过 `outputDevices` 事件发送，包含 `devices` 和 `status`。`status.requested` 是最后成功应用的设置；失败的新设置仍可留在前端选择框便于修改，不能误当成当前输出。失败附带 `detail`。设备设置命令在状态发送后才返回 ACK。

桌面 IPC：`sda:output-devices`、`sda:set-output-device`，订阅 `sda:output-devices`。所有 ACK 命令复用已有串行控制队列；设备设置另加事务队列，成功 ACK 后才写入设置。进程退出会清除实际输出状态。原生启动通过 `SDA_OUTPUT_SETTINGS` 接收保存的设置，缺省使用共享默认设备。

## 验证与限制

- Rust 回归：97 通过、0 失败、3 项原有忽略。覆盖既有 DSP、FIFO 和转换器回归。
- Windows 静音集成脚本：`node scripts/test-audio-output.cjs`。默认仅测共享；独占需显式 `--exclusive`，只能在本机且没有远程采集时运行。即使没有音源，独占初始化也可能使第三方回录会话失效，不能再把“静音”当作无影响。脚本不加载音源、不激活输出。
- 本机通过：稳定端点枚举、3 次连续共享切换、无效端点拒绝与原端点恢复、Realtek 耳机真实独占 48 kHz/2 声道、另一个 44.1 kHz 端点切换、暂停位置保持、`outputActive=false`。
- 前端类型检查、生产构建通过。独立 Electron 用户目录验证通过：通用选择器选择/应用、稳定 ID 保存、失败设置不覆盖已保存偏好、刷新页面恢复、深浅色与 1440/390 px 窗口无横向溢出、菜单位于视口内、无运行时错误、无播放。最终 release 静音设备联调通过，并已部署到开发版、重新打开可见窗口。
- 尚未现场验证：播放中的实际听感/爆音、物理拔插、蓝牙重连、RDP 会话切换、休眠唤醒。不能据接口测试声称这些硬件场景全部通过。
- 采用轮询而非端点通知，变化检测通常约 1 秒，慢驱动可能更久。驱动初始化同步调用可能造成切换短停顿；不承诺音频设备无缝交接。自动默认切换不保证旧设备淡出。
- 设备枚举中的格式是当前共享混合格式，不是设备全部支持的格式列表。独占候选没有覆盖所有可能的硬件格式，也不提供原生多声道直通或 bit-perfect 承诺。

### UU 远程问题复查

用户反馈独占与共享均在 UU 无声。检查到 SDA Windows 音频会话未静音、会话音量为 1；eConsole 与 eMultimedia 当时都指向 Realtek 耳机。一次 45 秒系统回录电平监测期间播放器始终暂停，零电平不能用来判定正在播放的捕获链路是否正常。

随后在 UU/GameViewer 服务端的 `streamer_log_20260908173203958_6032.1.txt` 找到 17:09:02 的 `AUDCLNT_E_DEVICE_INVALIDATED`，以及采集会话 `Inactive` / `OnSessionDisconnected`；后续可见日志没有新的采集启动记录。时间与本轮独占测试吻合，表明不能仅靠 SDA 切回共享来恢复 UU 已失效的旧会话。应在远程客户端关闭再开启声音以重建采集；若无效，需用户自行重连远程会话。本次没有主动终止 UU 服务或远程连接。

本轮恢复共享事件机制及原来的默认角色选择，并补充后端强制共享的远程模式；默认测试取消独占探测。最终 UU 接收端恢复仍须用户重建采集后确认，不能写成已经验证修复。

修复验证：最终 release 的共享设备切换、暂停位置保持、冲突参数在远程模式下归一化通过；独立 Electron 验证远程默认值、独占提示、设置持久化、原生进程重启后恢复、窄屏布局通过。用户实例已经更新并保存 `remoteCompatible:true`，实际为默认 Realtek 48 kHz 共享。测试没有再次打开独占，也没有自动播放音源。

后续依照 `player-roadmap.md` 逐项推进；本轮没有扩展到性能优化、无缝播放或上混。
