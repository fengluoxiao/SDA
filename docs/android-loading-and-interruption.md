# Android 导入准备与音频焦点

Android 和 iOS 在文件导入时均调用同一 MP4 音轨提取器，导入条目只有在压缩音轨准备完毕后才进入就绪状态。Android 在空闲时预加载 HRTF 渲染器，不创建音频输出流、不申请音频焦点；首次播放复用这份准备。

Android 的已准备压缩音轨属于当前队列，重复播放和上下曲可复用。对 Expo DocumentPicker 放在本应用 cache/DocumentPicker 下的新副本，只有成功完成提取后才用准备文件替代；外部文件及 content URI 不删除。共享解析器仍按 256 KiB 块处理，不增加整曲 PCM 缓存。关闭本机导入会话时释放准备文件，进程重启后的旧会话文件在下一次导入时清理。

播放器申请公共 AudioFocusRequest，使用与媒体输出一致的 USAGE_MEDIA/CONTENT_TYPE_MUSIC。焦点丢失调用原有原生暂停命令，保留文件描述符、解码器、FIFO 和播放时钟，不调用 stop/playUri，也不清空位置。

- 暂时失去焦点、短暂 duck 请求：记住原来是否播放，恢复焦点后自动续播。
- 永久失去焦点：保留暂停状态，用户按播放时重新申请焦点并从当前位置继续。
- 用户主动暂停：放弃焦点并取消自动续播；旧请求或旧歌曲的延迟回调被忽略。
- 申请焦点失败：保持暂停，界面不能把失败当成已经开始播放。
- 歌曲结束/停止：释放该播放租约的焦点，不能影响新歌曲的请求。

测试应覆盖压缩音轨准备顺序与文件所有权、暂时/永久打断、手动暂停后不自动恢复，以及真机上同一 generation 和非零位置的继续播放。蓝牙/硬件输出设备断开是另一种设备生命周期事件，不能仅凭焦点模拟测试宣称已验证所有设备切换。
