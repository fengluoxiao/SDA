# 个性化 HRTF：自适应生成与 SOFA 导入

更新日期：2026-09-10。实验功能；真实听者改善程度尚未验证。

## 当前流程

右侧耳廓面板的个性化 HRTF 提供参数化生成及个人 SOFA 导入。新测试不加载或筛选 SADIE II、KU100 等原有档案，也无需联网、AI 或 Python。

1. 暂停歌曲，戴好耳机并确认默认共享输出。测试声音使用系统默认设备，不跟随 SDA 指定输出；关闭系统空间音效，保持头朝前、佩戴不变。
2. 开始时快照当前中央房间布局，以该布局的实际方位、仰角、音箱名称逐只测试。7.1.4 测试 11 只定位音箱，2.0 测试 2 只；LFE 不承担方向定位，不作为位置题。没有固定的 12 方位池。
3. 每只音箱独立生成响应。回答“否”只替换当前音箱的参数，保持当前题；回答“是”保留该音箱响应并进入下一只。后面的重试不会重置前面已通过的音箱。
4. 固定位置完成后，在当前布局音箱之间依次进行移动试听，采用正式播放的 VBAP 音箱路由与已确认的音箱 HRIR。回答“否”重听当前实际路径，不再调整未用于正式播放的参数插值指数；回答“是”进入下一条路径。重听不会自动改善模型，持续无法确认可以结束测试；已确认音箱不会被暗中改变。
5. 全部完成后自动把每只音箱的已确认响应保存为同一份 pHRTF，记录布局、参数与反馈，并应用。没有旧 HRTF 基线或旧响应输入，也不设置重试次数上限；用户可主动结束。
6. 测试中改变布局会暂停，恢复快照布局可继续，或结束后按新布局开始；避免提示的位置与当前房间不一致。

## 按方向保存与插值

每个确认音箱保留独立的生成参数，保存为 `parameters.version:2` 的 `anchors`。精确音箱方向直接使用它已确认的参数，输出样本与试听逐位一致。通用导出网格的其他方向仍按球面弦距的反距离权重混合参数，但当前布局的对象播放和新移动测试使用布局音箱的 VBAP 合成，不使用这套参数插值来替代音箱路由。新测试固定指数为 2；旧档案仍保留原值以确保原响应不变。

移动测试固定使用同一组音箱响应，不会因后续题目重听改变先前路径。通过仍只代表视听主观确认，不是客观定位误差测量。

## 生成模型与限制

48 kHz、每耳 512 抽头的结构式近似：一阶球形头部声影滤波、双耳时间差、随方向变化的参数化耳廓凹口。双耳共用生成方法，不做逐耳或逐方向增益归一，不通过不断加音量把“否”变成“是”。

- ITD 两种近似：Woodworth `a/c × (θ + sin θ)` 与低频球形近似 `3a/c × |sin(az)cos(el)|`；`θ=asin(|sin(az)cos(el)|)`，`c=343m/s`。这是两个近似模式，不代表完整频率相关球面散射解。
- 独立连续生成等效半径 70–105 mm、凹口中心 6.5–10 kHz、凹口深度 3–12 dB，并选择一种 ITD 近似。范围限制物理模型参数，不限制生成次数；不存在预先计算好的响应候选列表。
- 耳廓凹口的仰角/前后映射是启发式合成，不是用户耳廓几何或实测规律。等效半径也是待试听参数，不能解释成测得头围。宽带 ITD 近似和单凹口无法充分描述真实耳廓、躯干或频率相关时延。
- 基础处理由 `parametric-hrtf.mjs` 同时供试听和后台生成使用。每耳公共 48 个采样延迟，附加远耳分数时延；不加入房间残响。测试电平默认 -30 dB，可在首题提交前调整，之后锁定。

是/否反馈不足以唯一求解个人 HRTF。本功能逐只音箱确认自行合成的响应，不是反演真实双耳响应，也不是个人测量。所有方向确认仍不能证明对任意节目、耳机或佩戴条件有效；视觉提示还可能提高主观确认率。

## 保存与正式播放

后台 worker 生成 433 个通用方向，并补齐不在通用网格上的音箱精确方向：方位角每 5°，仰角 -45/-30/0/30/45/60/90°，天顶仅一个方向。已确认音箱的试听和导出使用相同参数及函数，样本逐位一致。新移动试听只加载这些音箱响应，把单声道测试信号按 VBAP 增益送入各音箱卷积，使用 451 点曲线描述 2.4 秒路径，与三维标记共用位置函数。

用户数据目录 `personal-hrtf/hrtf-personal-<hash>/` 保存 `hrtf-set.json`、双耳 `.f32` 及 `assessment.json`。记录模型版本、生成参数和每次回答；摘要包含参数与记录，重复应用同一结果复用目录。`parametricHrtfVersion:1` 与 `source.measured:false` 明确区分合成与 SOFA 实测。dry/wet 指向同一文件，因此没有伪造的房间响应。

原生与网页渲染保留生成样本，不套旧数据校准、左右对称化或逐耳归一。应用等待原生确认，失败恢复原档案；恢复按钮保留。房间、监听及其他处理仍可能改变最终听感。生成文件与共享合成模块随安装包提供，不要求用户部署模型。

结果 schema v6 / `per-speaker-audibility` 保存生成参数、生成次数、回答总数与最近 1000 条回答；超过时标注历史已截断，避免连续重试占用无限内存；旧 schema v1–v5 档案只保留兼容读取、应用，不参与新测试。成功结果必须包含每个已确认音箱与其保存锚点一致的响应参数，拒绝混合不同参数的通过记录。

## SOFA 支持范围与数据处理

读取使用 NIST 来源的 [h5wasm](https://github.com/usnistgov/h5wasm) 0.10.3 / HDF5 WebAssembly，运行在 Electron 后台 worker。随桌面依赖打包，保留包内完整许可证；未修改该库。按照库文档处理 Electron 的 `navigator` 环境检测，并把 worker 和 WASM 依赖配置为 ASAR unpack。已验证真实 Electron 与 ASAR 布局下读取。

首版明确接受：

- `SimpleFreeFieldHRIR`，48 kHz，`Data.IR` 为 M×2×N。
- 8–4096 个方向，每耳 16–4096 个采样；输入最多 8,388,608 个采样，应用延迟后不超过 64 MB，源文件不超过 128 MB。
- 标准固定听者：位于原点、朝 +X、上方 +Z；接收器为米制笛卡尔坐标，左耳在 +Y、右耳在 -Y。
- 球面角度/米或笛卡尔米制声源坐标；统一转为正方位角向左、正仰角向上。仅接受一个测量半径，重复方向拒绝。
- `Data.Delay` 为 1×2 或 M×2；无单位按 SOFA 约定的采样计，支持采样或秒，范围 0–4096 samples。

逐耳应用显式延迟。整数延迟精确移位，分数延迟采用 33 抽头加窗 sinc，两耳共同增加 16 个采样的处理延迟。不从 HRIR 再提取并重复加入传播时延，不做逐方向均衡、增益归一或左右对称化。

SOFA 原始测量没有房间时，内部 wet 与 dry 相同，反射残差为零。用户数据下生成 `personal-hrtf/hrtf-personal-<hash>/`，记录原文件 SHA-256、来源、许可证、转换版本及处理步骤。相同输入与转换版本复用目录，转换成功后才原子发布目录。

不支持的格式、采样率、动态听者坐标或多距离数据明确报错，不自动猜测。导入来自用户的 SOFA 只说明数据来源，软件无法证明其中的被测者就是当前用户。当前方向插值沿用 SDA 现有渲染能力；高密度个人数据与高对象数的实时性能仍需实机验收。

## 信号链边界

- 匹配测试音通过独立 Web Audio 干声链，不更改播放器音量、房间、监听、耳机模拟或路由；关闭面板、结束测试或恢复歌曲播放时停止测试音。
- 正式应用走现有原生 HRTF 选择，不只是前端显示变化。原始立体声旁路没有 HRTF，因此不会产生变化。
- 开启匹配布局的外部房间档案时，个人 HRIR 保持为直达声，房间仅提供 `room - direct` 反射残差。按个人双耳主峰中较早的到达位置与房间 onset 做公共时间对齐，不分别移动左右耳；声床与逐对象渲染采用同一规则。反射仍保留原房间测量的双耳特征，不能视为个人实测 BRIR，主峰对齐也是近似。
- 原生切换先构建完整音箱滤波器，成功后一起替换档案、湿声权重和渲染器；构建失败保留原来的播放处理状态。
- 离线回归使用两个不同的合成个人响应，通过实际 Engine PCM 输出验证：房间开启时声床与逐对象两条路径均随档案变化，个人直达样本保留，房间旧直达被移除。此测试证明处理生效，不代表每位用户、每首歌都有同等明显的主观差异，也不以额外增益或音染制造差别。

### 测试与节目定位一致性

- 已修复新移动试听直接合成沿途 HRIR、正式播放却使用 VBAP 音箱混合的不一致。新记录添加 `renderMethod: speaker-vbap-v1`，旧测试记录不能冒充新路由验证结果。

- 测试采用干声、零扩散、头朝前的点对象。节目含对象扩散、多个相关声源、房间、监听处理或头部转动时不能要求输出与单一干声测试逐样本一致；动态曲线的采样与原生块间平滑也不是相同的时间实现。方向规则一致不等于已经验证每个听者的定位准确性。

- 本轮原生完整回归：99 项通过、3 项忽略；release 构建通过。未对用户的音频输出进行试听验证。
- 此次没有实现近场距离 HRTF、声源面积/扩散，也没有生成用户头耳几何或进行声学数值求解。

## 个人档案管理

完成测试自动保存到用户数据目录，支持同时保留多份；界面列出名称、方向数、生成/测量来源和当前使用状态。

- **切换**：选择已保存档案，等待播放器确认后显示使用中。暂停歌曲后操作，不要求重测或重新生成响应。
- **命名**：修改独立显示名称，不改动响应或测试记录。
- **另存为**：复制为新的独立档案，可自行命名；原档案保留。
- **导出**：使用 SDA 自有目录选择器，写出 `.phrtf` 文件。同名文件自动增加序号，绝不覆盖。
- **导入**：自有文件选择器同时接受 `.phrtf` 与 `.sofa`；导入后列入档案管理，用户选择切换，不自动覆盖当前听音设置。

已保存档案允许在歌曲播放中切换、命名、另存、导入和导出；定位测试仍要求暂停。切换等待原生确认，失败恢复原档案。界面回归在 `playing=true` 下验证档案管理可操作、定位测试不可开始。

`.phrtf` 为版本化 gzip JSON 包，包含完整 manifest、双耳 f32 响应、生成参数或 SOFA 来源、显示名称与测试记录。逐文件 SHA-256 校验；导入后使用包内响应，不依赖旧测量库或重新执行生成算法。同一 ID 和相同内容的重复导入复用档案；同 ID 不同内容拒绝覆盖。名称存于 `profile-info.json`，不会改动 manifest 的响应来源。

导入在 worker 中检查采样率、方向、处理格式、文件名、数据大小、有限采样和校验值，成功后原子安装；拒绝路径穿越、缺失资产及损坏数据。生成、SOFA 转换与档案打包模块均随软件内嵌。

验证：`personal-hrtf-library.test.cjs` 覆盖 worker 往返、逐字节响应一致、命名、副本、同名导出与损坏包拒绝；`personal-hrtf-library-ui.test.cjs` 覆盖切换、命名、另存为、自有导出目录选择器与导入。测试不播放声音。
