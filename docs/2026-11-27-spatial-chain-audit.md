# 五项空间音频研究方向的实现审计

基线：已接受的 iOS 0.9.40 / 990，源码 `89937f520c916d6dbf823954f46fe495fc63fce0`。
范围：研究辅助检查已有链路，修复可复现问题；本地定向验证与纯打包工作流分开。

## 研究与检查结果

| 方向 | 依据 | 本次检查结果 |
|---|---|---|
| 头追延迟 | [Rappin 等，动态双耳渲染延迟辨别，2025](https://doi.org/10.17743/jaes.2022.0195) | 现有 iOS 姿态经原生路径进入共享渲染器。发现连续姿态命令会独占队列容量，修为仅合并相邻有效姿态，保留最新一项。PCM、重置、设置及带回复命令维持原有顺序。 |
| 声音外化/世界定位 | [Brimijoin 等，头动对声音外化的贡献，2013](https://doi.org/10.1371/journal.pone.0083068) | 验证已有逆旋转、头顶/底部坐标、世界固定声床、LFE 和短反射路径。保持现有 990 的 HRTF、房间及混响参数。 |
| HRTF 时间与相位 | [Zaunschirm 等，时间对齐和扩散场约束，2018](https://doi.org/10.1121/1.5040489) | 原论文研究 Ambisonics，本次借鉴其延时/相干性评估思路。验证现有 ITD、分数延时、高频相位和滤波切换历史。另发现通用 SLERP 工具公式错误，并修复极大有限四元数的归一化溢出。 |
| 耳机补偿 | [Kulkarni、Colburn，佩戴引起的传递函数差异，2000](https://doi.org/10.1121/1.428571) | 保留左右耳补偿数据自身的延时、极性和增益。修复尚未出声的旧配置阻塞最新选择，补充同一配置重复下发时的去重，避免重新预热。 |
| 双耳去掩蔽/空间平衡 | [Bronkhorst、Plomp，双耳时间差/声级差与语音可懂度，1988](https://doi.org/10.1121/1.395906) | 这是语音噪声研究，不能直接当作音乐增益配方。检查现有世界坐标参考和头动不改变控制器的性质；修复有限异常值窄化/滤波溢出后检测器无法恢复的问题。普通有效信号的控制参数沿用原值。 |

## 可复现的缺陷

### 1. 连续姿态耗尽控制队列

容量 2 的队列连续推送 100 个姿态，修复前第 3 项被拒绝。修复后相邻有效姿态占一个槽位，最新姿态可接受，PCM 可正常进入第二槽位。不会跨越 PCM 或 ClearHeadPose 等控制边界合并，也不会吞掉无效命令的错误处理。

这项修复减少队列中的过期工作，没有增加预测器或改变音频时钟。实际端到端延迟仍包含传感器、调度、HRTF 分块、已渲染 PCM、耳机补偿及设备输出，不能以队列长度代替真机测量。

### 2. 耳机配置切换预热

长 FIR 配置 B 仍未出声时选择 C，旧实现仍等待 B 完整预热和淡入，然后才处理 C。现在在分块边界替换尚未出声的 B；已开始发声的过渡保留卷积历史并连续完成。不同左右耳延时、极性和输出分块延迟保持。

相同配置的重复请求按已有静态滤波响应和 preamp 比较后忽略，避免预热不断重启。比较使用现有频域数据，不复制滤波器或增加音频缓存。

### 3. 掩蔽检测异常恢复

`f64` 有限值转 `f32` 仍可能溢出为无穷；可表示的极大 `f32` 也可能使滤波状态溢出。原检测器此后无法从正常信号恢复。现在忽略不可表示的参考值，在非有限滤波输出时恢复该轴滤波状态和组功率。此修复针对检测器恢复能力，不代表主观去掩蔽能力已经提升。

### 4. 四元数工具

原 SLERP 将角度 theta 用作分母，正确分母应为 sin(theta)，导致结果不保持单位长度，连端点也会缩放。修为标准短弧球面插值并归一化结果。普通归一化的原快速路径保留，极大有限输入改用 f64 求模。

仓库引用检查确认 SLERP 工具目前没有被播放主路径调用，因此不能把这个工具错误归因于当前听感。归一化工具则用于现有姿态校验和世界坐标变换。

## 验证记录

- 修复前四项新增回归均失败：姿态队列耗尽、最新配置等待、异常掩蔽参考无法恢复、SLERP 非单位长度。
- 35 项定向原生测试通过，覆盖姿态/世界坐标、双耳独立响应、ITD、分数延时相位、短 HRTF 过渡、控制队列、掩蔽检测，以及 7.1.4、360RA、声床和立体声的原生合成 PCM 回调一致性。
- 后续 12 项配置/反射测试通过，其中 7 项与前述集合重合；共 40 项不同的定向原生回归通过。新增同配置重复下发先复现预热饥饿，再验证修复；反射检查覆盖首达、镜像、尾部能量和单次残差合入。
- 没有向 GitHub 打包流程加入测试步骤。

本轮使用 Windows 原生共享核心和合成信号，没有完成实体耳机端到端延迟、真人外化评分或音乐去掩蔽听测。耳机佩戴造成的实际响应变化也无法仅靠软件单元测试量化。
