# 系统空间音频起播与暂停预缓冲

适用现有 SystemSpatial360 输出链，包括 360RA、Audio Vivid 7.1.4，以及共享这条链的 ALAC 系统输出。保留原响度测量、250 ms 起播储备和 500 ms 重缓冲储备，不添加扫描或缓存。

此前向 Apple 提交 PCM 只在喂入新压缩数据时执行。如果系统暂时停止接收媒体数据，同时解码队列已达到前馈限制，喂入循环会等待消费，却不再尝试提交已解码 PCM；初始输出、恢复或 EOF 尾部可能停在这个状态。现在 status 轮询也推进 pump，恢复播放时立即提交现成 PCM，不依赖新压缩包触发。

暂停且尚未起播时，允许完成已有上限内的首次预缓冲；达到就绪即停止继续预读。同步器保持暂停，未开始播放的时间戳仍从零开始。就绪判断同时考虑已解码但尚未提交的 PCM，与用户是否已按播放分开；界面不会仅因无需响度预分析而把零 PCM 状态报告为准备完成。恢复时使用现成 PCM，不重启解码器、不重新攒一次储备。

最终的 Apple 提交仍服从 isReadyForMoreMediaData，响度测量未就绪时仍不提交需要平衡的首包。短 EOF、空 EOF、明确暂停、媒体恢复及大计数边界包含在独立的生产 Swift 调度测试中；该测试不加入 iOS 打包工作流。Windows 主机无法运行 AVFoundation 或 xcrun，实体设备的实际延迟须另行确认，不能由源码检查冒充。

播放输入已开始提供暂停预缓冲后，若用户再开启音量平衡，继续当前解码器的有界流式测量，不重启全曲分析或丢弃已读前缀。所有共享 speaker feed 返回一致的测量就绪标记。初始尚未读入播放数据的 MPEG-H 全曲参考分析保持原策略；本次空间平衡不添加另一套预扫描。

独立泵送也明确区分正常 EOF 和真正的供数中断：正常播完冻结时钟但不增加 underrun 计数；已关闭的输出不会再访问解码器。该更改避免状态轮询被误记为一次末尾欠载。
