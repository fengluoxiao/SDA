# 空间听感增强规划

记录日期：2026-09-10。

状态：用户随后授权启动第 1 项，已实现实验性定位匹配、档案应用与 SOFA 导入，详见 [个性化 HRTF 实现](personal-hrtf.md)。第 2、3 项仍未开始。以下未交付的候选路线不代表已实现；真实听者收益与高对象数个人数据性能仍待验证。不涉及实测 BRIR 监听室重放或双音箱串扰消除。

## 1. 个性化 HRTF

用户补充要求：按 pHRTF 技术路线设计，不把普通档案选择或 EQ 调整包装成已获得个人 HRTF。现有实现明确区分感知数据库匹配与用户导入 SOFA；个人测量设备、几何建模和数值求解尚未实现。

### pHRTF 数据与实现路径

pHRTF 并非唯一固定算法，必须区分响应来源：

1. **个人实测**：用耳道入口测量麦克风、已知方向声源和受控环境获取个人多方向 HRIR，校正测量系统并核验坐标与时延。普通耳机不能自行测出完整个人 HRTF。
2. **个人几何建模**：从有尺度的头部、耳廓及躯干几何进行声学数值求解。头宽或普通照片不足以直接产生可靠全频段响应；扫描、算力和验证成本须专项调研。
3. **听觉测试驱动的匹配或估计**：通过方向辨识测试，从实测人群数据筛选或拟合适用响应。应标注“匹配”或“估计”，不能称为本人实测；拟合需在未参与调整的方向上验证，不能只调整音色偏好。

工程上先统一个人数据接入与原生渲染接口，研究 SOFA 导入，核验采样率、左右耳、坐标、距离及显式延迟，避免重复计入响应内时延。不逐耳、逐方向独立归一化，以免破坏相对定位线索。个人档案记录来源、处理步骤、生成方法和版本，支持安全切换与回退。

仓库初查已有 SADIE II 多受试者档案与转换脚本（例如 `scripts/build-hrtf-subject.mjs`），可作为匹配研究起点，不等于用户个人 HRTF。没有个人测量或扫描数据时，开箱即用方案应明确为经过听觉验证的匹配或估计；本人实测路线则需要相应个人数据。

目标：改善前后混淆、垂直定位和声音头内化，使双耳渲染更适合具体听者。不保证所有人获得相同改善。

候选路线：

- 筛选可合法内嵌分发的多受试者 HRTF 数据，核实许可证、测量条件、坐标、采样率和均衡方式。
- 提供引导试听，用已知方向的声音逐轮比较候选档案；让用户按定位自然度与稳定性选择，而非按“更响、更亮”选择。
- 在有效范围内研究头部尺度与双耳时间差调整，保持时间差、频谱和方向插值的一致性，不把简单改 EQ 称为个性化 HRTF。
- 保存个人档案，允许旁路和恢复默认；不要求 AI、个人扫描设备或用户部署模型。

验证：等响条件下比较前后误判、仰角辨识、外化程度及音色变化；检查动态方向插值是否平滑、切换是否爆音，以及多对象实时开销。通用数据筛选不等同于测得用户本人的 HRTF。

## 2. 近场声源渲染

目标：让耳边与远处声源具有不同的距离感，而非仅靠调低音量表示远近。

候选路线：

- 研究带距离维度的实测近场 HRTF 或经验证的距离变化模型，联合处理双耳电平差、时间差及频谱变化。
- 明确声源、听者坐标和物理距离。ADM 等格式的归一化坐标不能直接解释为米；缺乏真实距离时使用明确标示的用户场景映射，不伪称母版原始距离。
- 连续插值方向和距离，限制极近距离的数值发散，避免越过头部时突变。
- 与房间模块协调直达声和反射路径，避免重复计算距离衰减或混响；房间关闭时仍可使用近场双耳线索。

验证：固定方向的距离试听、不同距离下的双耳响应测量、穿越近场的连续轨迹，以及高对象数性能。物理传播电平与试听等响对比应分开记录，不用隐藏增益补偿掩盖模型问题。

## 3. 声源面积与扩散渲染

2026-09-10：已接入可旁路的原生实验版本、元数据范围、独立扩散分量和手动试听设置，见 [实现与验证](source-extent.md)。完整物理分布模型、乐器识别和网页独立渲染不在本轮实现中。

目标：让弦乐、合唱等声源具有可控的空间范围，同时保持需要聚焦的人声清晰，避免所有声音都退化为点声源或模糊声团。

候选路线：

- 核实各输入格式的宽度、高度、深度和扩散元数据含义，再映射到渲染参数；不能假定不同格式参数等价，也不把没有元数据的内容当成已知乐器。
- 研究分布声源采样、能量归一与受控去相关，避免简单复制同一信号至多个方向造成梳状滤波、音量叠加或相位抵消。
- 将声源几何范围与扩散程度分别控制；零范围应退化为现有点声源行为。
- 自适应分配采样点与计算预算，平滑范围变化；与房间扩散处理分工，避免重复扩散导致人声变虚。

验证：范围变化时的响度与频响稳定性、单声道兼容性、空间连续性、定位清晰度及最坏情况 CPU 开销。不能仅凭三维图形变大认定音频渲染已经实现。

## 后续实施原则

建议顺序：个性化 HRTF → 近场声源渲染 → 声源面积与扩散渲染。正式排期时先核查现有代码与数据，复用已具备的能力，逐项完成后再推进下一项。

- 每项先做可旁路的原生音频原型，再接入界面；实际改变音频链路才记为实现。
- 共用明确的坐标、插值和个人档案约定，避免三项各自维护不一致的声学模型。
- 发布参数以可追溯资料和实测为依据，区分物理数据、用户偏好与工程假设。
- 不以偷偷加响度、强制归一或增加混响冒充空间改善；验证时可另设明确标示的等响比较。
- 不改变现有文件播放稳定性；验证切歌、拖动、开关切换及高对象数场景。
- 本文不承诺工期；数据授权和算法验证完成后再估算开发成本。
