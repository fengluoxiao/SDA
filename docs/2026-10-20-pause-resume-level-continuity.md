# 暂停续播的音量与时钟连续性

本地原生输出原先在暂停和继续时增加渲染 epoch。工作线程将其视作需要重建播放时间线的操作，清掉已渲染但尚未消费的立体声 FIFO，并把消费时钟推进到渲染头。空间/响度/峰值控制状态已经位于该渲染头；丢弃中间节目后可能听到不连续的电平或恢复过程。

现在本地暂停仅关闭回调消费并冻结渲染，保留已渲染节目、消费时钟与 DSP 包络。继续时，有现成节目就重新启用回调，即使 FIFO 已满也能播放；空队列仍沿用正常预缓冲。重复暂停/继续不会增加 epoch。真正的定位、换曲或重置仍会清掉旧节目。远端同步分支继续使用原来的共享时钟策略。

共享渲染器增加了两项回归：真实工作线程及回调读取暂停前预排队的 2048 帧，续播逐样本相同且时钟不跳；重复开关保留节目增益、最终响度控制和真峰值状态，同时验证重置仍创建新 epoch。两项通过。iOS 打包来源记录增加 protocol.rs 哈希，便于在成品中确认包含这项修改。

此修改只调整暂停边界，不改变连续播放的空间平衡、HRTF 或响度/峰值策略。此前 b5c93bd 的 28 段连续场景、19 段空间开启输出和相应 DSP 源哈希仍作为连续播放验证；暂停边界另由上述回归检查。试听页另行验证暂停/继续不改变 HTML 音量系数。未把软件检查当作实体设备听感验收。
