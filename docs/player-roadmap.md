## 1. 音频输出管理

目标：用户能够明确选择输出设备；切换耳机、蓝牙、远程会话或系统默认设备时，播放器能恢复，并准确说明当前输出方式。

### 当前实现（2026-09-09）

- Windows 输出改为直接调用 WASAPI；`output_manager.rs` 管理稳定端点 ID、实际共享/独占初始化、断连与切换。音源和空间渲染仍由原 render worker 管理。
- 系统设置新增输出设备面板，沿用通用选择器；支持跟随默认、固定端点、应用、刷新、失败重试及偏好保存。
- 渲染保持 48 kHz；`device_output.rs` 转换到实际设备时钟。面板单独显示设备采样率、声道数、实际模式及 WASAPI 缓冲时长。
- 设备列表由独立 COM 线程每秒扫描，不在音频循环查询属性库。指定端点失联保持音频消费时钟，等待用户重试；跟随默认可自动切换/恢复。
- 详细行为、协议、测试与限制见 [音频输出管理](audio-output-management.md)。

### 实现顺序

- [x] 枚举稳定 ID、名称、系统常规默认端点、可用状态及共享混合格式；独占格式按候选实际初始化，不宣称返回设备全部能力。
- [x] 设置面板提供“跟随系统默认”和“指定设备”，使用已有通用选择器，成功应用后保存偏好。
- [x] 明确区分选择值与实际设备、共享/独占模式、设备采样率；渲染采样率单独说明。
- [x] 切换仅重建输出，旧端点先淡出关闭，再打开新端点并淡入；失败尝试恢复旧设置。独占不能保证新旧同时打开，因此改为有短暂停顿的串行交接，不承诺无缝切换。
- [x] 保留原渲染引擎、FIFO、暂停与其他 DSP 设置；静音测试验证连续切换不改变暂停位置或开启播放。
- [ ] 完成真实拔插、蓝牙、RDP 连接/断开和休眠唤醒的硬件验收；恢复策略已经接入，不能把静音接口测试当作这些场景通过。
- [x] 指定设备不可用时停止消费 FIFO 并提示；允许另选设备，不自动切到外放。这里保持播放时钟，不篡改用户的暂停开关。
- [x] 真正独占初始化已在本机 Realtek 耳机上成功；打开失败返回原因，恢复旧设备，不伪装成功。
- [x] 桌面控制命令串行化；默认端点不可用时最多每 5 秒重试，固定端点手动重试；状态变化写入诊断日志。

### 验收

- 空闲、暂停、播放三个状态都能切换设备，暂停时不会自行开始播放。
- 连续切换不产生重复输出、旧设备占用、错误播放位置或设置丢失。
- 共享与独占状态来自实际打开结果，独占失败不会把播放器卡死。
- 验证本机耳机、蓝牙以及 RDP 场景；缺少真实设备的场景标为未验证。
- 自动测试使用合成数据或离线渲染，不自动播放用户歌曲。

### 本轮交付记录

- 原生回归：97 通过、0 失败、3 项原有忽略；Web 构建和 TypeScript 检查通过。
- `scripts/test-audio-output.cjs`：真实端点枚举、连续共享切换、无效 ID 失败恢复、真实独占成功、48/44.1 kHz 设备切换、暂停位置和输出未激活检查通过。全过程无歌曲、无音源。
- Electron 的设置保存与界面验收记录见功能文档。真实播放时的切换听感、物理拔插、蓝牙、RDP 和休眠仍需现场验收。
- 没有进入第 2 阶段，也没有自动提交或推送。
- UU 无声问题后续：UU 日志在独占测试时段记录 `AUDCLNT_E_DEVICE_INVALIDATED` 和音频采集会话断开，后续未见重建；因此共享也无声并不只取决于当前访问模式。新增后端强制的远程兼容模式，恢复共享事件机制和 eConsole 默认角色，默认测试不再探测独占。已告知用户在 UU 端关闭再开启声音重建采集，未主动断开其远程连接。最终远程听音待用户确认。

## 2. 空间渲染性能优化

目标：高对象数 ADM、逐对象 HRTF、长房间卷积和对象显示同时工作时保持稳定。

### 实现范围

- [ ] 固定性能基线：对象数量、布局、滤波器长度、运动状态、房间和硬件开关。
- [ ] 分别测量解码、数据传输、原生渲染、音频回调和前端绘制；记录分位耗时、最坏耗时、欠载与内存。
- [ ] 根据实测瓶颈优化卷积批处理、滤波器缓存与更新、静音尾声处理、数据复制和线程调度。
- [ ] 对象显示与音频时钟解耦，使用时间戳与插值，避免主线程卡顿拖住音频。
- [ ] 检查切歌、拖动和模式切换时的资源回收，防止缓存无界增长。

### 验收

- 使用相同输入和硬件记录优化前后结果；不以减少对象、忽略元数据或降低默认精度冒充性能提升。
- 离线输出与基线在明确的数值容差内一致，位置和增益事件时序正确。
- 给出已测配置的稳定范围；不宣称所有机器都可无条件运行最高配置。

参考现有 `native-object-hrtf-performance.md`、`direct-object-hrtf.md` 和 `stutter-handoff.md`。

## 3. 无缝播放与下一首预解码

目标：专辑连续曲目切换时没有人为停顿、重复采样或重新初始化造成的断音。

### 实现范围

- [ ] 增加有内存上限的下一首准备状态，预读容器、元数据并解码必要的首段 PCM。
- [ ] 正确处理各格式的编码器延迟和尾部填充；区分未知信息与确认的有效采样范围。
- [ ] 在连续输出时钟上衔接有效采样，避免每首重新打开设备。
- [ ] 区分音源状态与输出设备状态；处理曲目间对象、布局及元数据变化。
- [ ] 明确房间与 HRTF 尾声策略，防止旧对象泄漏或突然截断。
- [ ] 用户跳曲、重排队列、删除待播项或拖动时取消过时的预解码任务。
- [ ] 下一首损坏或准备失败时正常报错，不破坏当前播放。

### 验收

- 用可拼接的测试波形验证边界没有漏样、重样、插入静音。
- 保留曲目间原本录制的静音；无缝播放不等于自动交叉淡化。
- 暂停、跳曲和队列改动不会触发意外播放，预解码资源有界。
- 各支持格式分别记录验证情况，不把单一格式通过等同于全部格式无缝。

## 4. 立体声空间上混

目标：普通双声道可以近似扩展到现有虚拟音箱布局，人声居中稳定，环境成分具有包围感。

### 实现范围

- [ ] 独立开关与强度控制，默认关闭，保留原始双声道试听。
- [ ] 使用左右相关性等信息估计中心和环境成分；不能简单复制左右声道到所有音箱。
- [ ] 保护中心人声与低频的稳定定位，限制后方和高度输出。
- [ ] 处理相位、去相关和增益平滑，避免梳状滤波、摆动、拖尾和切换爆音。
- [ ] 输出送入已有布局、HRTF、房间和监听链路，并遵守现有耳机模拟互斥规则。
- [ ] 界面标明“上混估计声道”，不冒充原生 Atmos 对象或原始制作元数据。
- [ ] Atmos/ADM 等原生空间输入不自动再次上混。

### 验收

- 单声道人声保持中心稳定；反相、硬左右、低频和环境录音不发生明显异常。
- 对比电平有明确参考，不能仅靠变响制造提升感。
- 强度为零回到原始路径；开关切换平滑，输出峰值受控。
- 分别验证 2.0、5.1、7.1.4、9.1.4、9.1.6 的路由和缺失声道处理。
