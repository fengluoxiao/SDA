# C 增益组合的跨歌曲候选（2026-10-08）

## 用户确认与通用化边界

用户已确认 C 人声可听，纯 master 试听仍不可听，D/E 两种子组提升都可听，并要求把 C 的组合用于其他歌曲。

原 C 额外提高 Obj12–24；这些编号不是跨歌曲的“人声”标签。通用候选保留 master +2 dB、辅助层最多 +6 dB，但以已有空间元数据/路由定义辅助层。不读取歌曲名、时间窗、对象 ID、声音强弱或语音内容，也不假定编号最前的两路就是主干。

**这是可选增强设计，不是忠实原混音、独立人声识别、Apple 算法复制或已验收的 C 精确复刻。辅助层会包括其他空间乐器/环境声，部分前方内容不会得到原 C 的固定 +6 dB。** 用户仍需听新候选，不能用旧 C 的通过替代新候选验收。

## 实现

- 共享 master preamp 请求 +2 dB；混音后左右联动，位于既有峰值保护之前。
- 辅助层强度 0..+6 dB，默认 **0 dB**。master 默认也保持 0 dB。
- 依据世界坐标：耳平面前方 ±45 度为主层；侧后方及绝对高度至少 30 度为完整辅助层；中间以平滑权重过渡。阈值是增强方案选择，不是标准强制的声场解释。
- 对象使用原位置；床声道使用布局的 canonical 世界路由，不跟随头转做增益判断。LFE 不进行辅助提升。
- 只提升、不单独压低前景。增益按 128 样本更新目标，以约 30 ms 的有界斜率过渡；当前 Source 的 PCM/元数据 gain 字段不变，额外源标量应用于所有该源的直达/空间线索/反射激励。
- 普通与并行混音器使用同一个增益函数，仍使用原 HRTF、位置和时间戳；默认关闭时走 unity 旁路。
- 余量不足时既有完整输出峰值保护会共同作用，不能保证所有曲目的动态毫无变化或永远不削波。导出另行核查 4 倍过采样峰值。

新增控制：`Engine::set_spatial_layer_gain_db`，原生 JSON `setSpatialLayerGain`/`gainDb`，共享 MobileEngine 方法及 iOS 低层 `spatialLayerGain` 命令。与 `setMasterPreamp` 分开控制，两项组合成 +2/+6 配方。没有新增 UI/偏好保存、发布包或默认开启。
