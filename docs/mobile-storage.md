# 移动端文件归属与临时文件回收

## 保留的内容

Android 在 `files/playback-library`、iOS 在 `Application Support/playback-library` 保留一份播放文件。文件以原始导入内容的 SHA-256 和实际播放扩展名命名；同一首歌重复导入不会再保存一份。压缩容器需要先提取音轨时，保存提取后的音轨和歌曲元数据，移除多余的文件选择器副本。资料库音频不属于可随意淘汰的缓存，也不按容量上限自动删除。

两端保存原生播放队列。iOS 新增原子队列文件并恢复队列；复制歌曲的过程中先写临时文件，成功后再安装到最终路径。失败导入释放提取会话，并仅回滚未被原生队列引用的新文件。不把逐歌曲响度测量、PCM 或渲染结果保存为缓存。旧 iOS `sda.loudness.*` 和 Android `sda-loudness` 数据在启动时清除，播放不再读取或写回它们。导入时刚完成的测量只做一次内存交接；当前歌曲的增益作为播放状态保留，点进度条不会重新做整曲分析。

## 自动回收

- 导入成功并保存队列后：释放提取临时会话和原文件选择器副本。
- 重复导入、格式不支持或准备失败：回收本次选择器副本和未完成的提取文件。
- 每次进程首次启动：回收已知命名规则的 SDAR 房间/HRTF 解包目录、遗留提取文件和未完成的原子导入文件。
- Android 根据当前随包目录回收旧版本内置房间响应，保留当前版本和不匹配内置命名的文件。
- Android 同时回收未被保存队列引用的旧选择器副本。未引用的提取封面按 64 MiB 预算淘汰，队列引用的封面受保护。

进程内重建 React/Expo 模块不会重新扫除正在导入或播放的文件。删除范围只包含 SDA 管理的目录、明确匹配的临时文件名，并检查路径归属及符号链接；不会递归清空 Documents、Caches 或资料库。

## 旧版 iOS 的限制

旧版 iOS 没有持久化导入文件的完整归属表。遗留的 UUID 命名 MHAS 是可重新提取的临时文件，可以回收；旧 DocumentPicker 进行一次后台完整 SHA-256 去重：只合并内容完全相同的副本，保存队列引用的路径和每一份独有歌曲。无法确认归属或内容不同的文件会保留，不能把它们全当成缓存删掉。系统显示的“文稿与数据”也包含导入歌曲，不能据该总量断言有相同容量的缓存可以清除。

## 验证

- `node --test apps/mobile/test/import-native-queue.test.mjs`：两端导入成功、失败、重复、临时所有权释放及后台队列恢复。
- `python scripts/test-mobile-storage.py`：运行真实 Kotlin 文件清理策略，覆盖队列/资料库保护、遗留资源、封面预算、进程内重复启动和符号链接边界。
- `python scripts/test-ios-storage.py`：供 macOS/Xcode 运行真实 Swift 清理策略，只操作隔离的测试目录，覆盖遗留提取文件、队列/旧歌曲保护和符号链接边界。
- iOS 原生编译和设备存储变化仍需在 Xcode / 安装后的应用验证。Windows 上的测试不代表 iPhone 实测。
