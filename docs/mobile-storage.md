# 移动端文件归属与临时文件回收

## 保留的内容

Android / iOS 新导入的播放副本放在 `playback-sessions/sda-session-进程号-UUID`，用于本次进程中的后台读取、定位及切歌。冷启动清理旧的已知会话目录，避免每次运行继续积累播放副本。外部原始歌曲和旧资料库独有歌曲保持保护；不将它们混同于可清空的计算缓存。

播放队列只属于本次运行的原生会话：冷启动和更新后重启都以空列表开始；后台播放、自动切歌和 React 前台恢复依靠仍在运行的原生队列。两端不再写入播放列表或上次选择的歌曲，启动时清除旧 iOS queue.json / sda.queue.selected 和 Android sda-playback-queue。iOS 旧记录只临时用于保护迁移期间的歌曲文件，随后删除记录，不交给播放器恢复。

复制歌曲过程中先写临时文件，成功后再安装到播放副本路径。失败导入仅回滚未被当前原生会话引用的新文件。音频 PCM、渲染结果和逐歌曲响度结果不落盘；旧 iOS sda.loudness.* 和 Android sda-loudness 在启动时清除。当前会话的整曲响度、峰值和采样数等少量参数跟随已加载音源，往返切歌和定位不重扫同一有效源。参数按内容标识、路径、大小和修改时间校验，移出队列且不再加载或模块销毁时释放。原始歌曲和无法确认归属的独有文件受保护。

## 自动回收

- 导入成功并保存队列后：释放提取临时会话和原文件选择器副本。
- 重复导入、格式不支持或准备失败：回收本次选择器副本和未完成的提取文件。
- 每次进程首次启动：回收已知命名规则的 SDAR 房间/HRTF 解包目录、遗留提取文件和未完成的原子导入文件。
- Android 根据当前随包目录回收旧版本内置房间响应，保留当前版本和不匹配内置命名的文件。
- Android 同时回收未被保存队列引用的旧选择器副本。未引用的提取封面按 64 MiB 预算淘汰，队列引用的封面受保护。

进程内重建 React/Expo 模块不会重新扫除正在导入或播放的文件。删除范围只包含 SDA 管理的目录、明确匹配的临时文件名，并检查路径归属及符号链接；不会递归清空 Documents、Caches 或资料库。

## 旧版 iOS 的限制

旧版 iOS 没有持久化导入文件的完整归属表。遗留的 UUID 命名 MHAS 是可重新提取的临时文件，可以回收；旧 DocumentPicker 进行一次后台完整 SHA-256 去重：只合并内容完全相同的副本，保留旧队列曾引用的路径和每一份独有歌曲。无法确认归属或内容不同的文件会保留，不能把它们全当成缓存删掉。系统显示的“文稿与数据”也包含导入歌曲，不能据该总量断言有相同容量的缓存可以清除。

## 验证

- `node --test apps/mobile/test/import-native-queue.test.mjs`：两端导入成功、失败、重复、临时所有权释放及后台队列恢复。
- `python scripts/test-mobile-storage.py`：运行真实 Kotlin 文件清理策略，覆盖队列/资料库保护、遗留资源、封面预算、进程内重复启动和符号链接边界。
- `python scripts/test-ios-storage.py`：供 macOS/Xcode 运行真实 Swift 清理策略，只操作隔离的测试目录，覆盖遗留提取文件、队列/旧歌曲保护和符号链接边界。
- iOS 原生编译和设备存储变化仍需在 Xcode / 安装后的应用验证。Windows 上的测试不代表 iPhone 实测。
