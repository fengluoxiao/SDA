# 8351B 参考监听室

更新：2026-11-17。音频基线 `4ae960ba976b96294ebdd44820374a8324fc2032`，版本 0.9.40，移动端构建号 950。

## 开启方式与范围

iOS 与 Android 在设置 → 空间渲染 → 渲染预设中选择 **8351B 参考监听室**；Windows 与 macOS 在设置 → 空间 → SDA Spatial → 监听预设中选择同名项目。默认仍为原 SDA Spatial，切回即可恢复原来的房间线索。系统空间音频旁路时保存选择，恢复 SDA 渲染后使用；SDAR 文件自带的渲染参数保持优先。

此预设采用厂家归一指向性和明确假设的房间仿真，保留当前共享 HRTF 的直达响应与连续对象方向定位。它不是完整实测 83xx 音色、GLM、Aural ID 或个性化实测房间，也不承诺耳机能重现实体音箱和低音炮的身体低频感。没有获得绝对轴向低频响应，因而没有凭空加入“真力低频 EQ”。

- 8351B GLL：https://assets.ctfassets.net/4zjnzn055a4v/1WcRAwuQu6hUCHa9UT990V/8e16d8615c0befd4d3ceded84f178aae/Genelec_8351B.gll
- 原始 GLL SHA-256：`41f01aa835cdcf03c57b81ad5eccbbfcd60eb37a21ce7ac32b770ffec67c743d`。
- 离线提取工具为 gll-tools v0.1.1，未作为产品依赖，也未打包其工具或代码。保留厂家版权和数据来源，不打包原 GLL、图片或商标。
- 数据共 107 份方向响应、每份 241 个频点，有效带宽标注为 50–16000 Hz。按 meridian-major 顺序重建 3×37 网格，共享前后极点；没有沿用通用 CSV 导出器错误的角度列。
- 轴向数据为归一响应。使用幅度推导的最小相位近似，不宣称使用了已验证的音箱绝对实测相位；带外采用端点延续。

`apps/native-renderer/assets/genelec-reference/` 包含归一数值、固定系数、manifest 和 NOTICE。`scripts/build-genelec-reference.py` 仅依赖 NumPy，可从方向性数据、全部声道布局、native-prepared 直达库和既有共享接收 HRTF 重新生成。manifest 记录来源、接收响应及系数的 SHA-256。

## 仿真与处理路径

房间假设 6×5×3.2 米，听者耳高 1.2 米，声源距离 1.2 米；采用一、二阶矩形镜像反射、各面分频段吸收、分数延时和声源离轴指向性，再用同一共享 HRTF 接收。没有计算低频波动声学房间模态。

固定库包含 48 个唯一方向、15 种布局，覆盖 360RA 的三个底部声道。反射长度 4608 采样（96 ms），运行时统一滤波容量 6144。反射总线替换标准短残差，不叠加两套房间；独立对象仍保持连续方向直达卷积。主声道不合并为单声道，LFE 保留既有独立路径，立体声低频保留校准继续工作。

全部方向使用同一个残差校准标尺；离线校准检查 20–500 Hz 的双耳能量和分频段相干变化，以避免某个方向大幅低频抵消。默认强度下，最差窄带变化约 −1.31 dB，分段能量变化约 −0.98 至 +0.20 dB。这是保守的参考反射，不能把这个预设称为已验证的完整音箱低频复刻。空间平衡继续使用 `directional-detail-measured-headroom-v2`，参考房间另有独立标识 `genelec8351b-reference-room-v1`。

## 运行与切换

系数编译进入 Rust 原生库，不下载模型、不缓存歌曲、不整曲分析，也不在 JS 中传输音频。移动端从播放锁外准备滤波；桌面从协议控制线程准备。准备完成后一次提交，在原卷积历史上过渡，不重启解码器，不清 PCM、队列、对象或播放时钟。扩展卷积历史保留已有频谱年龄与 overlap，切回短滤波时保留已分配历史，避免尾音突然丢失。

移动端使用 generation、layout 和 selection epoch 检查，拒绝过期准备结果；成功应用后才保存设置。桌面按当前选择的共享响应集准备，兼容默认 542 方向和手动选择的 17 方向，不强制换成维度不匹配的资源。切换歌曲和布局会加载相应布局的固定资源。默认 SDA Spatial 的直达 HRTF、后方及头顶优化、增益余量和真峰值保护均继续保留。

## 打包与限制

四个平台共用同一 Rust 系数库。iOS 与 Android 记录算法和固定资源哈希；桌面也验证实际原生程序的算法标识与系数摘要。安装包保留 NOTICE，不把研究工具、歌曲或临时 PCM 加入仓库。

Windows ARM64 编码器改用上游月末归档，并固定压缩包 SHA-256 与 ARM64 PE 标识；月末归档上游保留两年，需在 2028-10-31 前维护更新，避免再次依赖只保留十四天的日构建。不会用 x64 程序冒充 ARM64，也不把内部编码器 ZIP 混入用户 Release。

## 验证结果

- 574 项渲染回归通过，46 项依赖专用环境或显式离线输入的测试保持 ignored；176 项原生播放器回归通过，7 项环境专用测试保持 ignored。
- 覆盖 15 种布局的固定响应、360RA 三个底部声道、残差强度、预设往返、真实延迟尾音、卷积历史扩展、立体声低频保留、无效 ID、过期布局，以及真实原生队列、暂停状态和解码进度保留。
- 移动端与桌面 TypeScript 检查、iOS 9 项资源校验、Android 2 项来源清单校验、预设与独立导出资源检查通过。
- 用 `In Your Eyes` 的 15–35 秒、90–120 秒及 `Matasaburo` 的 0–20 秒分别回放标准/参考模式，共 6 次真实 E-AC-3/JOC 原生 PCM。默认与上一版的最大差异不超过 3.0e-7，RMS 差异不超过 2.4e-8，属于浮点累加舍入量级；没有改变默认频响。
- 参考模式的实际输出与默认不同。三段节目中 20–80 Hz 能量变化约 −0.10 至 +0.02 dB，80–200 Hz 约 −0.47 至 −0.26 dB；这支持“保守的反射变化”，不支持“完整 83xx 低频复刻”或“低频一定更厚”的结论。独立 FFmpeg 测得真峰值均低于 −1 dBTP。
- 实际下载并校验新 Windows ARM64 编码器归档，SHA-256 为 `40029da82e02abf0d12491e23666e710b7a8943d13501594cf38e6135b95efba`，内部 PE machine 为 `0xaa64`。

这些结果不等于真机听感或温控持续性能已经验收。本轮没有连接真实手机或 macOS 音频设备进行试听。
