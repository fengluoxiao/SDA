# 移动端导入准备与原生播放队列

## 立体声响度参考

ALAC/MP3 在导入文件时调用 `prepareStereoTrack`，完成一次新的整曲原生测量后才把队列行标为就绪。iOS 与 Android 保留与内容哈希、本地路径、文件大小和修改时间绑定的内存结果。播放和重复播放使用这个结果，不重复扫描，也不改变原来的整首固定增益、立体声 0 dB 额外增益和峰值保护。

不把立体声响度结果写入磁盘，不读取持久化响度缓存。重新导入会重新测量。应用进程重建后，内存测量结果不存在；旧列表中的歌曲首次播放仍会做完整测量。文件发生变化时也要重新测量，禁止先播放未校准的 PCM。取消或失败的分析必须关闭分析句柄。SDAR 的文件调优不进入这条流程。

## Android 原生队列

Android 和 iOS 都在原生端处理曲尾与下一首，不依赖 React 定时器。Android 使用串行控制执行器进行启动、停止和切歌，解码线程在实际音频排空后提交下一首操作。操作执行前检查媒体令牌和当前歌曲，避免过期的曲尾、通知栏操作把新歌曲再跳一次。重复模式为顺序、列表循环、单曲循环；显式上一首/下一首仍移动到相邻歌曲。

切换时保留前台媒体服务，替换播放租约，不先停止服务再从后台重启。没有下一首或出现错误时结束当前租约。JavaScript 只提交操作、管理导入和显示原生快照，不再负责 Android 的曲尾自动切歌。

队列保存完整 URI、真实播放文件名、原始显示名、歌曲信息、播放模式和选中歌曲。Android 导入的自有临时副本移动到 `filesDir/playback-library`；不移动用户的外部原文件。压缩音轨提取后的 `.mhas/.av3a/.ac4` 名称与 URI 一起保存，恢复列表时不把它当原来的 M4A 再提取一次。恢复列表不会自动开始播放。此保存项不包含 PCM、渲染结果或响度测量。

## 验证

- `node --test apps/mobile/test/import-native-queue.test.mjs`：导入准备、测量失败、重复播放、真实文件名恢复、后台原生状态同步和双重切歌防护。
- `python scripts/test-android-native-queue.py`：用本地 Gradle Kotlin 编译器在 JVM 上运行真实队列/参考管理类，覆盖顺序、循环、手动切歌、文件变化、取消和句柄关闭；需要 `JAVA_HOME` 与 `GRADLE_USER_HOME`。
- Android `:sda-core:compileDebugKotlin` 与移动端 TypeScript 检查。
- Windows 机器不能完成 iOS 真机编译；需要 macOS CI。后台长时间连播还需要实体设备验收。
