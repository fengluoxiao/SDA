# 移动端整曲参考、响度与工作副本

本次修复保持播放的 48 kHz 重采样、HRTF、对象、空间处理与最终峰值保护。整曲分析不需要把 12 路 PCM 先全部重采样为 48 kHz：AV3A 分析器在原采样率上执行完整 BS.1770 计量，公开播放时钟仍换算为 48 kHz。`inputSampleRate`、`measurementSampleRate` 与播放 `sampleRate` 分别记录真实含义。

## 解码与测量并行

AV3A 分析借鉴连续解码时向计量端交付参考的方式：解码线程与完整 BS.1770 / 固定 HRTF 参考计量并行，交接队列最多两帧。它不积累整曲 PCM、不保存磁盘计算结果，也不把开头几秒的测量当成整曲响度。对象场景保留原来的场景参考，不用扬声器床层规则替代。

取消分析或切换歌曲时先关闭接收端，再等待解码线程退出；生产线程即使正在等待交付，也能退出，不遗留后台分析任务。

2026-11-03 在 Windows 本地使用同一首约 235 秒、44.1 kHz / 12 声道 AV3A、同一 HRTF 运行独立进程对照：串行 10.234 / 9.781 秒，并行 7.562 / 7.078 秒。完整参考 JSON 精确相同，包括 11,269,294 个播放时钟帧、2,321 个源计量块、LUFS、真峰值与固定 HRTF 参考。这是该电脑的实测，不代表 iPhone 或 Android 真机耗时。

## 一次选择的节目增益

普通立体声保持 0 dB 格式补偿；具有多声道床层或对象的 AV3A 与其他已识别沉浸式节目保持 +1.8 dB。两声道 AV3A 不因扩展名而获得沉浸式补偿。

声道床层能量达到目标，并不保证经过 HRTF 相干合成后的双耳参考也达到目标。对经过验证的静态 AV3A 多声道床层，整曲分析另外计算固定 SDA HRTFHQ / 7.1.4 / 零人头姿态的节目参考。它不跟随听者位置、实时设置或后续音乐片段，不进行音量骑乘。

固定参考复用实际渲染器的床层标签、目标扬声器和 VBAP 折叠规则；只重采样少量固定 HRIR，使用多个输入 FFT 和两个输出 IFFT 汇总完整节目。LFE 使用实际渲染器的滤波/压缩规则。原始节目和参考输出各自执行整曲计量，选取两者中更保守的一次节目增益：

`gain = min(master_gain(source), master_gain(canonical_reference))`

`master_gain` 保持 −18 LUFS 目标、真峰值约束和不放大安静节目的规则。后面的 +1.8 dB 格式补偿及独立最终峰值保护照常工作。原始参考和固定参考都存入当前会话参数，既没有按歌写死 dB，也没有叠加第二条随时间变化的归一化包络。定位、重复播放和开关音量平衡保留同一份选定参数。

新 `renderedReference` 为可选字段，包含参考配置、布局、HRTF 清单 SHA-256、采样率与完整测量值。缺少它的旧参考仍可读取。对象型 AV3A 保持其已验证的场景参考，不把对象传输声道猜成固定扬声器。Apple 系统输出使用原始节目测量，忽略 SDA 固定参考字段。

## 文件与启动

冷启动和更新后重启以空播放列表开始，旧队列记录被移除；仅在原生播放仍然运行时，React 页面恢复才重新连接本次会话队列。

新导入的播放工作副本进入按进程/UUID 区分的 `playback-sessions`。下次冷启动清理以前的已知会话目录，当前会话的后台播放、定位和切歌保持文件可读。清理不遍历符号链接，不删除原始歌曲、未知目录或旧资料库独有歌曲。历史计算结果不读取、不持久化；当前会话只持有少量节目参数及有界工作缓冲。

## 验证含义

需要分别验证源计量、固定参考预测、实际渲染输出、定位后实际增益与发声对象活动，以及安装包代码/资源。编译通过不代表听测通过；模拟器和 Windows 原生回调也不能宣称替代 iPhone/Android 真机与蓝牙设备测试。
